# 관리자 메뉴 UI/UX 기획

## 개요
이 문서는 관리자 메뉴의 정보 구조와 반응형 UI/UX 방향을 정리합니다.

기준 전제는 아래와 같습니다.

- 관리자 메뉴는 일반 사용자 메뉴와 분리합니다.
- 관리자 메뉴는 웹 사용 빈도가 높다고 가정하고 웹 중심으로 설계합니다.
- 모바일과 태블릿에서도 동일한 기능을 제공하되, 레이아웃 밀도만 다르게 적용합니다.
- 현재 앱의 다크 배경 + 네온 포인트 스타일을 유지합니다.

관련 문서:

- `docs/menu-planning.md`
- `docs/admin-permissions.md`
- `docs/auth-flow.md`

## 설계 목표

### 1) 운영 효율
- 관리자는 로그인 후 빠르게 운영 작업으로 진입할 수 있어야 합니다.
- 공지 등록, 시즌 선택, 팀 등록, 경기 등록이 2단계 이내로 도달 가능해야 합니다.

### 2) 문맥 유지
- 공지사항을 제외한 운영 데이터는 시즌 문맥 안에서 관리합니다.
- 관리자는 항상 "현재 어떤 시즌을 수정 중인지" 명확히 인지할 수 있어야 합니다.

### 3) 반응형 일관성
- 웹, 태블릿, 모바일 모두 같은 정보 구조를 공유합니다.
- 단, 화면 폭에 따라 탐색 방식과 카드 밀도만 조정합니다.

### 4) 기존 디자인 일관성
- 현재 홈 화면의 다크 톤, 네온 그린 강조, 라운드 카드 스타일을 그대로 확장합니다.
- 관리자 화면만 별도 브랜드처럼 보이지 않도록 사용자 화면과 같은 디자인 언어를 유지합니다.

## 관리자 메뉴 진입 방식

### 기본 정책
- 일반 사용자는 관리자 메뉴를 보지 않습니다.
- `admin`, `super_admin`만 홈 상단 설정 버튼을 통해 관리자 메뉴에 진입합니다.
- 하단 사용자 탭에 관리자 메뉴를 추가하지 않습니다.

### 진입 흐름
1. 관리자 로그인
2. 홈 화면 우측 상단 설정 버튼 노출
3. 설정 버튼 클릭
4. 관리자 대시보드 진입

권한 없는 사용자가 직접 진입한 경우:
- 화면 진입 시 즉시 권한 확인
- 권한 없으면 `권한이 없습니다` 안내 후 홈으로 이동

## 정보 구조

관리자 메뉴는 아래 구조를 기본안으로 사용합니다.

1. `대시보드`
2. `공지사항 관리`
3. `시즌 관리`
4. `권한 관리` (`super_admin` 전용, 추후 확장)

## 메뉴별 역할

### 1) 대시보드
- 관리자 첫 진입 화면
- 오늘 처리할 작업 요약
- 현재 활성 시즌 표시
- 최근 공지, 예정 경기, 빠른 작업 버튼 제공

권장 구성:
- 상단 상태 카드: 현재 시즌, 관리자 권한, 미완료 작업 수
- 빠른 작업: `공지 작성`, `시즌 선택`, `경기 등록`
- 최근 활동: 최근 공지, 가까운 경기 일정

### 2) 공지사항 관리
- 공지 등록
- 공지 수정
- 공지 삭제
- 첨부 파일 관리

정책:
- 공지는 시즌과 무관한 전역 데이터로 운영합니다.
- 일반 사용자 `공지` 화면과 작성/수정 기능은 분리합니다.

### 3) 시즌 관리
- 시즌 목록
- 시즌 생성
- 시즌 상태 확인
- 시즌 상세 진입

시즌 생성 폼 기본 항목:
- 시즌명
- 시즌 설명

정책:
- 운영 데이터의 시작점은 시즌입니다.
- 시즌 관리는 공지사항 관리처럼 별도의 관리자 페이지로 분리합니다.
- 관리자 대시보드 하단에 시즌 생성 폼이나 시즌 목록을 직접 노출하지 않습니다.
- 시즌 목록의 각 행 또는 카드를 누르면 시즌 운영 전용 페이지로 이동합니다.
- 시즌 상태는 `active`, `inactive`만 사용하고 동시에 하나의 시즌만 `active`가 될 수 있습니다.
- 시즌 상세 안에서 `팀 관리`, `경기 관리` 기능으로 이동합니다.
- 즉, `팀 관리`와 `경기 관리`는 독립 1차 메뉴가 아니라 `시즌 관리`의 하위 운영 기능입니다.

시즌 상세 > 팀 관리 운영 규칙:
- 진입 시 해당 시즌에 저장된 팀 편성 데이터를 그대로 로드하고, 같은 화면에서 수정/삭제/추가를 처리합니다.
- 동일 시즌 안에서 한 선수가 여러 팀에 중복 배정되면 저장을 차단하고 즉시 안내합니다.
- 경기 데이터에 연결된 팀은 삭제를 차단하고, 어떤 팀이 차단됐는지 팀명으로 안내합니다.

### 4) 권한 관리
- 사용자 역할 변경
- 관리자 권한 부여/회수
- 운영 정책 데이터 수정

정책:
- `super_admin` 전용으로 분리합니다.
- 초기 버전에서는 메뉴만 고려하고 실제 구현은 후순위로 둡니다.

## 반응형 레이아웃 기준

### 웹
관리자 메뉴는 웹에서 아래 구조를 기본으로 사용합니다.

- 좌측 사이드바
- 상단 작업 헤더
- 우측 메인 콘텐츠

권장 특징:
- 좌측 사이드바에 관리자 메뉴 고정
- 상단에 현재 시즌, 사용자 역할, 빠른 액션 표시
- 메인 영역은 카드, 리스트, 폼을 조합한 운영 대시보드 형식
- 목록과 상세를 2단으로 나누는 레이아웃 허용

웹에서 적합한 이유:
- 관리 메뉴가 많아도 탐색이 빠릅니다.
- 공지 목록, 시즌 목록, 경기 목록 같은 운영형 데이터에 적합합니다.
- 폼 입력과 요약 카드가 동시에 보이므로 작업 전환이 쉽습니다.

### 태블릿
- 축소형 사이드바 또는 상단 탭형 보조 탐색 사용
- 카드 2열 중심 레이아웃 유지
- 상세 입력 폼은 전체폭 사용

정책:
- 웹 구조를 유지하되 정보 밀도만 낮춥니다.

### 모바일
- 설정 버튼으로 관리자 허브 진입
- 첫 화면은 `관리자 허브` 카드형 대시보드
- 세부 화면은 단일 컬럼 기반으로 이동

정책:
- 하단 탭에 관리자 메뉴를 넣지 않습니다.
- 웹의 사이드바를 모바일에서 그대로 축소하지 않습니다.
- 모바일에서는 큰 액션 카드와 명확한 섹션 분리로 탐색합니다.

## 화면별 UX 원칙

### 대시보드 UX
- 첫 진입 시 가장 중요한 액션을 상단에 배치합니다.
- 운영자가 즉시 행동할 수 있는 CTA를 제공합니다.
- 단순 통계보다 실제 작업 진입 버튼이 우선입니다.

예시:
- `공지 작성`
- `현재 시즌 열기`
- `경기 등록`

### 리스트 화면 UX
- 웹에서는 리스트 + 상세 2단 분할을 허용합니다.
- 모바일에서는 리스트에서 상세 화면으로 이동하는 구조를 사용합니다.
- 정렬, 상태, 최근 수정일 같은 관리 정보는 한 줄 메타 데이터로 노출합니다.

### 입력 폼 UX
- 공지 작성, 시즌 생성, 경기 등록 폼은 동일한 카드 스타일을 사용합니다.
- 긴 폼은 섹션별로 나누고, 저장 버튼은 하단에 고정하거나 명확히 반복 노출합니다.
- 필수값과 현재 선택된 시즌을 상단에 명시합니다.

### 피드백 UX
- 저장 완료, 수정 완료, 삭제 완료는 현재 앱의 모달 또는 토스트 패턴으로 일관되게 처리합니다.
- 권한 부족, 시즌 미선택, 필수값 누락은 즉시 안내합니다.

## 디자인 언어 기준

### 유지해야 할 요소
- 다크 배경4
- 네온 그린 중심의 포인트 컬러
- 둥근 카드와 부드러운 라운드 버튼
- 대비가 명확한 텍스트 계층

### 관리자 화면에 추가할 요소
- 현재 시즌 상태 배지
- 관리자 권한 배지
- 작업 상태 배지

주의:
- 네온 컬러를 모든 카드에 과하게 쓰지 않습니다.
- 강조가 필요한 CTA, 선택 상태, 활성 상태에만 제한적으로 사용합니다.
- 운영 화면은 정보 밀도가 높으므로 장식보다 가독성을 우선합니다.

## 권장 구현 우선순위

### 1차
- 관리자 대시보드
- 공지사항 관리
- 시즌 관리

### 2차
- 시즌 상세 내부 팀 관리
- 시즌 상세 내부 경기 관리

### 3차
- 권한 관리
- 운영 로그
- 세부 권한 분리

## 현재 권장 결론

초기 관리자 메뉴는 아래 방식으로 구현하는 것이 가장 적절합니다.

1. 홈 상단 설정 버튼으로만 진입
2. 웹에서는 사이드바 기반 관리자 대시보드 사용
3. 모바일에서는 카드형 관리자 허브 사용
4. 공지를 제외한 운영 기능은 모두 시즌 상세 안에서 처리
5. 현재 앱의 다크 + 네온 스타일을 그대로 유지

이 구조는 현재 문서에 정의된 권한 기준과 메뉴 정책을 유지하면서도, 웹 중심 운영 UX에 가장 잘 맞는 방향입니다.
