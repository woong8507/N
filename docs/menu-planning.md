# 메뉴 기획 정리

## 개요
이 문서는 현재 앱의 사용자 메뉴 구조, 관리자 메뉴 구조, 시즌 기준 운영 원칙, 홈 상단 액션 버튼 정책을 정리합니다.

기본 전제는 아래와 같습니다.

- 일반 사용자는 조회 중심 메뉴만 사용합니다.
- 관리자 기능은 일반 사용자 메뉴와 분리합니다.
- 공지사항을 제외한 운영 데이터는 모두 시즌 기준으로 관리합니다.
- 권한 기준은 `profiles.role`을 사용합니다.

관련 문서:

- `docs/auth-flow.md`
- `docs/admin-permissions.md`

## 사용자 메뉴 구조

초기 일반 사용자 메뉴는 아래 5개로 고정합니다.

1. `홈`
2. `일정`
3. `리그`
4. `팀`
5. `공지`

### 1) 홈
- 오늘의 경기
- 내 경기 요약
- 최신 공지
- 빠른 이동

역할:
- 상세 화면을 대체하지 않고, 요약과 진입 허브 역할만 수행합니다.

### 2) 일정
- 전체 일정
- 나의 일정
- 경기 결과
- 경기 상세

정책:
- `나의 일정`은 독립 메인 메뉴로 분리하지 않습니다.
- `일정` 내부 탭 또는 필터로 처리합니다.

### 3) 리그
- 리그 순위
- 팀별 성적

정책:
- 초기 버전은 순위 중심으로 단순하게 운영합니다.

### 4) 팀
- 팀 목록

정책:
- 팀 상세 화면은 만들지 않습니다.
- 현재 데이터 구조상 팀명과 인원 수 중심으로 목록만 제공하는 구성이 적절합니다.

### 5) 공지
- 공지 목록
- 공지 상세
- 첨부 파일 열람

정책:
- 일반 사용자는 공지를 조회만 할 수 있습니다.
- 작성, 수정, 삭제는 관리자 전용 기능으로 분리합니다.

## 관리자 메뉴 구조

관리자 메뉴는 일반 사용자 메뉴와 섞지 않고, 별도 운영 영역으로 관리합니다.

초기 관리자 메뉴는 아래 2개 축으로 정리합니다.

1. `공지사항 관리`
2. `시즌 관리`

### 1) 공지사항 관리
- 공지사항 등록

정책:
- 공지사항은 시즌과 무관하게 전역으로 운영합니다.
- 일반 사용자 `공지` 화면과 작성 기능은 분리합니다.

### 2) 시즌 관리
- 시즌 목록
- 시즌 생성
- 시즌 상세

시즌 생성 기본 입력:

- 시즌명
- 시즌 설명

시즌 상세 안에서 아래 기능을 운영합니다.

- 팀 등록
- 경기 스케줄 등록
- 시즌 Active, Inactive 기능 필요

정책:
- 공지사항을 제외한 운영 기능은 모두 시즌 하위에서 처리합니다.
- 관리자는 항상 특정 시즌 문맥 안에서 데이터를 생성하고 수정해야 합니다.
- 시즌 등록/목록/운영 이동은 공지사항 관리와 동일하게 별도의 관리자 페이지에서 처리합니다.
- 관리자 대시보드 하단에 시즌 등록 폼을 직접 넣지 않습니다.
- 등록된 시즌 목록에서 시즌을 선택하면 해당 시즌 운영 전용 페이지로 이동합니다.
- 한개의 시즌만 Active 가능하며  나머지 시즌은 자동으로 Inactive로 변경되어야 됩니다. 
- active된 시즌 기준으로 일반유저 화면에서 팀, 경기일정, 경기결과 등 노출이 되어야 된다. 

## 시즌 기준 운영 원칙

아래 기능은 시즌별 데이터로 관리합니다.

- 팀 등록
- 경기 스케줄 등록
- 경기 관련 푸쉬 발송

이 구조를 쓰는 이유는 아래와 같습니다.

- 시즌이 바뀌어도 데이터가 섞이지 않습니다.
- 관리자가 현재 어느 시즌을 운영 중인지 명확합니다.
- 이후 결과 입력, 순위 관리, 참가자 관리 기능을 같은 구조에 확장할 수 있습니다.

권장 흐름:

1. 관리자 로그인
2. 시즌 목록 진입
3. 시즌 선택 또는 시즌 생성
4. 시즌 상세에서 팀/경기/푸쉬 관리

## 홈 상단 버튼 정책

홈 상단 우측 액션 버튼은 아래 기준을 따릅니다.

- 돋보기 버튼은 제거합니다.
- 일반 사용자는 프로필 버튼만 노출합니다.
- 관리자가 로그인하면 설정 버튼(톱니바퀴)을 추가 노출합니다.

정리:

- `member`: 프로필 버튼만 노출
- `admin`: 설정 버튼 + 프로필 버튼 노출
- `super_admin`: 설정 버튼 + 프로필 버튼 노출

설정 버튼의 의미:

- 관리자 메뉴 진입
- 추후 `공지사항 관리`, `시즌 관리`, `권한 관리`로 연결할 수 있습니다.

## 권한 기준

권한은 `public.profiles.role`을 기준으로 처리합니다.

권장 역할 값:

- `member`
- `admin`
- `super_admin`

권한별 메뉴 기준:

- `member`: 사용자 메뉴만 노출
- `admin`: 사용자 메뉴 + 관리자 진입 가능
- `super_admin`: 사용자 메뉴 + 관리자 진입 가능 + 추후 권한 관리 확장 가능

주의:

- 메뉴 숨김만으로 권한을 처리하지 않습니다.
- 실제 생성/수정/삭제 권한은 Supabase 정책 또는 서버 로직으로 함께 차단해야 합니다.

## 현재 확정 사항

이번 기획에서 확정한 내용은 아래와 같습니다.

1. 사용자 메뉴는 `홈`, `일정`, `리그`, `팀`, `공지` 5개로 운영합니다.
2. `나의 일정`은 `일정` 내부 기능으로 둡니다.
3. `팀` 메뉴는 `팀 목록`만 제공합니다.
4. 관리자 기능은 `공지사항 등록`, `시즌 생성`, `팀 등록`, `경기 스케줄 등록 및 푸쉬 발송`으로 시작합니다.
5. 공지사항을 제외한 관리자 기능은 모두 시즌 기준으로 관리합니다.
6. 홈 상단의 돋보기 버튼은 제거합니다.
7. 관리자가 로그인하면 홈 상단에 설정 버튼을 노출합니다.

## 추후 확장 후보

향후 아래 기능은 필요 시 확장합니다.

- 시즌 상태 관리
- 경기 결과 입력
- 시즌별 순위 관리
- 관리자 권한 관리
- 운영 로그
- 세부 관리자 권한 분리
