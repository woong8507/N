# 메뉴 기획 정리

## 개요
이 문서는 현재 앱의 사용자 메뉴 구조, 관리자 메뉴 구조, 시즌 기준 운영 원칙, 홈 상단 액션 버튼 정책을 정리합니다.

기본 전제:
- 일반 사용자는 조회 중심 메뉴 사용
- 관리자 기능은 일반 메뉴와 분리
- 공지사항을 제외한 운영 데이터는 시즌 기준
- 권한 기준은 `profiles.role`
- 일정 메뉴는 구글 캘린더 형식의 월간뷰를 기준으로 운영

관련 문서:
- `docs/auth-flow.md`
- `docs/admin-permissions.md`
- `docs/calendar-event-planning.md`

## 사용자 메뉴 구조
초기 일반 사용자 메뉴는 아래 5개로 고정합니다.
1. `홈`
2. `일정`
3. `리그`
4. `팀`
5. `공지`

### 1) 홈
- 오늘의 경기
- 내 일정 요약
- 최신 공지
- 빠른 이동

### 2) 일정
- 월간 캘린더 그리드 (구글 캘린더 형식)
- 날짜별 일정 목록
- 일정 등록 모달

일정 유형:
- 공휴일
- 경기
- 휴가
- 출장
- 기타

정책:
- `나의 일정`은 독립 메인 메뉴로 분리하지 않고 `일정` 내부 필터로 제공
- 필터: `전체`, `경기`, `공휴일`, `휴가`, `출장`, `기타`, `내 일정`

### 3) 리그
- 리그 순위
- 팀별 성적

### 4) 팀
- 팀 목록

### 5) 공지
- 공지 목록
- 공지 상세
- 첨부 파일 열람

## 관리자 메뉴 구조
초기 관리자 메뉴:
1. `공지사항 관리`
2. `시즌 관리`
3. `회원 관리`

### 공지사항 관리
- 공지 등록/수정/삭제

### 시즌 관리
- 시즌 목록
- 시즌 생성
- 시즌 상세
- 시즌 상태 전환 (`active`, `inactive`)

시즌 상세 하위 운영:
- 팀 관리
- 경기 관리

경기 관리 입력 기준:
- 장소(`3F`, `4F`)
- 시작/종료 시간
- 팀 A vs 팀 B
- 팀별 2명 선택

### 회원 관리
- `admin`: `department`, `status` 수정
- `super_admin`: `role` 수정
- 삭제 버튼은 회원을 물리 삭제하지 않고 `profiles.is_deleted = true`로 소프트 삭제
- `is_deleted = true` 회원은 회원 관리 목록에서 비노출

## 시즌 기준 운영 원칙
시즌별 데이터:
- 팀 등록
- 경기 스케줄 등록
- 경기 푸시 이력

정책:
- active 시즌은 1개만 허용
- 일반 사용자 화면은 active 시즌 데이터 중심으로 노출

## 공휴일 운영 원칙
- 공휴일은 통합 캘린더에 포함
- 연도 단위 자동 동기화 기본
- 데이터 소스: Nager.Date (KR)
- 동기화 및 수동 보정은 관리자 전용

## 홈 상단 버튼 정책
- 돋보기 버튼 제거
- `member`: 프로필 버튼만 노출
- `admin`, `super_admin`: 설정 버튼 + 프로필 버튼 노출

설정 버튼:
- 관리자 메뉴 진입

## 현재 확정 사항
1. 사용자 메뉴는 `홈`, `일정`, `리그`, `팀`, `공지`
2. 일정 메뉴는 월간 캘린더 중심
3. 공휴일/회원 일정/경기 일정을 통합 조회
4. 공휴일은 자동 동기화 + 관리자 보정
5. 경기 등록은 시즌 상세의 경기 관리에서 처리

## 추후 확장 후보
- 주간뷰
- 일간 타임라인뷰
- 반복 일정
- 관리자 세부 권한 분리
